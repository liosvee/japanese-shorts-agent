# Japanese Shorts Agent

Run from the repository root. Use the repo's ignored project directory. The host's language and format are Japanese, Japan and Shorts. Pair Japanese copy with an English interpretation. The project's .mcp.json registers the vidIQ server. Authenticate with /mcp in Claude Code and check local Agent-Reach access. Use the current credential and cost instructions in docs/research-integration.md.

1. Follow prompts/00-research-next.md to initialize or resume the research run, save actual vidIQ responses, run the Agent-Reach collector, analyze candidates and persist Claude's decision. The commands are `python -m jp_shorts research-init`, `research-collect`, `research-import`, `research-analyze` and `research-decide`; consult the prompt for arguments. A niche decision updates the project. For a video, start a topic run with the selected niche ID. Never retroactively edit a decided plan.
2. Follow evolution/WORKFLOW.md and evolution/SCHEMA.md. Begin learning with the selected niche's stable ID or its actual Japanese/English name, ja, JP and short. Rank verified Japanese Shorts, save real evidence, then run refresh and sync. Inspect the resulting brief and knowledge. A sync that returns pending is local work, with a retry still due. Resume the same learning run when continuing the same video.
3. After the topic decision and learning refresh, run `python -m jp_shorts.agent_brief PROJECT`. It prints the project-relative research-brief.json path for the active pair of runs. The source is private under PROJECT/.evolution/. A niche-only or insufficient-evidence decision does not release a writer.
4. Follow packets.md. Use script.ja.txt for the editor's script input. Keep script.en.txt, claims.json, packaging.md, thumbnail plan and storyboard under the project. The writer and editor never sync raw evidence or approve spending. Send the editor the script only after it exists and passes the writer's checks.
5. Before generation/render, include both actual packet files, the script/translation and the real plans/manifest in the host's application receipt through `production_inputs` if not already bound as facet artifacts. Do not include research-brief.json or raw evidence as a production input. The packet files live in the project's agent-handoffs/ directory for this reason. Re-issue an editor packet and reapply after script edits. Run the packet check plus the host's apply, verify and gated production commands. Only report final visual QA if the real export was inspected.
